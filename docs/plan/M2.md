## Notes for the cards ahead

What M1 built that M2 uses, and what it left for M2 on purpose:

- **VFS-18** owns the episode states of section 4.1. The architecture document has a state
  diagram and a test that fails when diagram and code disagree, so the enum in
  `packages/core/enums.py` and the diagram change together.
- **Job handlers for voice and render.** `apps/worker/demo_render.py` runs voice, resolve
  and render in one process. The pipeline needs the same steps as queued jobs: a voice job
  that stores narration through the storage adapter and keeps its word timings, and
  `render.scene` jobs per scene followed by `render.join`. `render_scenes` already encodes
  only scenes whose file is missing, so a `render.scene` job is one call for one scene.
  These handlers belong to the first card that needs a rendered video through the queue,
  which is VFS-25 at the latest. If they turn out to be more than that card can carry,
  they become a card of their own.
- **Job types without a handler.** The pipeline (VFS-18) queues the job types of every
  state, but handlers arrive card by card and milestone by milestone: `qc.run` and
  `export.pack` in M4, `agent.critic` in M6. A job whose type has no handler fails with
  "No handler is registered", and the episode stops there with a visible reason. VFS-25
  has to say where the M2 demo ends (after the render) and show that as the expected
  end, not as an error.
- **VFS-19 and VFS-20**: the recorded responses of the seven skills for the sample episode
  go into `samples/recordings/`. The `direct` skill's recording must produce
  `samples/lighthouse_keeper/episode_spec.json` exactly, so the demo in the interface and
  `make demo-render` show the same video. Every file there needs an `ASSETS.md` row.
- **The bundled voice** only knows the sample's narration. When the owner edits a
  narration line at the plan gate on a machine without the voice model, the voice job
  fails with the message to run `make models` (question Q-022). VFS-25 has to decide how
  the demo test edits the plan: an edit that keeps the narration, or the model installed.
- **VFS-55, VFS-56, VFS-57** touch real command line tools on the host. They are built and
  tested against mocks. Anything that needs the owner's Claude or ChatGPT login is parked
  as a follow-up card, as the Unblock protocol says. `DEV_MAX_SPEND_USD` stays 0.
- **VFS-23, VFS-24, VFS-59**: the mockups win over the written spec. They are in the Design
  canvas linked from the design document, not in `docs/design/`.
- **VFS-25** replaces the note in the CI job `e2e-demo`: from then on the uploaded demo
  video comes from an idea run through the interface, not from `make demo-render`.
