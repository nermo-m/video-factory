# M1 Spec and render: task list

Milestone goal (design doc section 15): all schemas, resolver, render engine with every
primitive, the `night_scrolls` theme, Kokoro adapter, audio mix, contact sheet, golden-frame
tests, the original sample spec and assets.

**Done when:** `make demo-render` turns the sample spec into a correct 45 second video
inside the worker image.

M1 started while two M0 cards (VFS-7, VFS-8) were parked for the owner. Build rule 1 allows
that: parked cards do not hold up the next milestone.

## Notes for the cards ahead

- **VFS-11** also checks what a JSON Schema cannot: a statistic's `claim_id` and a visual's
  `asset_id` must exist in the same spec, scene ids must be unique, and a word cue must not
  point past the end of the narration.
- **VFS-12** adds the check against the theme's `capabilities.json` (text styles, overlay
  types, sprite names, sound cue IDs, transitions), so the planner cannot ask for something
  the renderer cannot draw. Every theme asset needs an `ASSETS.md` row, and all of it must
  be original or permissively licensed.
- **VFS-13 and VFS-16** wire the `render` CI job, which until then passes with a notice and
  fails as soon as a render test exists without being wired up. Golden frames are made and
  compared inside the pinned worker image.
- **VFS-14**: the Kokoro model files are downloaded by `make models`, never committed. When
  they are missing the adapter returns bundled sample audio, so demo mode and CI still work.
- **VFS-17** measures the render time for RN-11 and records it in the README.
